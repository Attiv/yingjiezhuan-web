# 整部游戏的流程与关卡框架

游戏内容全部是数据：引擎读 `src/data/game.json`，那是从自己持有的原版盘里转出来的
**整部《三國志英傑傳》**——6045 步流程、610 幕插剧（其中 417 幕有舞台记录、120 幕明确载入场景图）、70 场战斗、
58 张战场地图、129 名武将。下面说这份数据长什么样、引擎怎么消费它。

```
原版盘 ──hero-tools original extract/pack──▶ original/{extract,pack}
                                              │
                     tools/build_campaign.py  │  剧本 / 战斗 / 武将 / 道具 → JSON
                     tools/build_stages.py    │  剧情舞台：地图、摆人、地名条 → JSON
                                              ▼
                     src/data/game.json（1.4 MB）+ src/data/items.json + src/data/stages.json
                                              │
                        src/data/game.ts      │  装配成 Level / Script
                                              ▼
              src/rules/*（规则）  src/story.ts（流程）  src/stage.ts（剧情舞台）  src/main.ts（界面）
```

重新生成：

```bash
python3 tools/build_campaign.py                    # 先更新stages，再生成game/items/strategies等JSON
python3 tools/build_stages.py                      # 仅重新生成src/data/stages.json
python3 tools/make_full_assets.py <EXTRACT> <PACK> # → public/assets/**（图、音乐）
```

生成脚本只做格式转换（繁中原样保留，只清掉参考包里混进来的韩文模板字），不改台词、不改数值；
输出末尾会自检「缺失标签 / 缺失关卡 / 缺失地图」，都应为 0。

## 1. 流程脚本

一份脚本从头演到尾，对话、旁白、选择、营地、单挑、战斗、结局都只是其中的一步（`src/story.ts`）。

| 步骤 | 写法 | 作用 |
|---|---|---|
| 对话 | `{ t: 'say', who, text }` | 头像按 `who` 查 `faces` 表，等玩家点一下 |
| 旁白 | `{ t: 'text', text }` | 没有头像 |
| 章节 | `{ t: 'title', text }` | 居中横幅（「序章　群雄起兵討伐董卓」） |
| 插画 | `{ t: 'picture', key }` | 原版事件插画 448×288 摆在舞台中央；空串 = 收起 |
| 舞台 | `{ t: 'stage', id }` | 登记这一幕的场景与可通行网格（见 §10） |
| 动作 / 等待 | `{ t: 'action', op }` / `{ t: 'wait', ms }` | 动作完成后才推进下一步，移动按原版网格寻路并逐格播放 |
| 自由交谈 | `{ t: 'room', id, options?: [{ who, label, prompt, set?, goto? }] }` | 留在场景内交谈、购物、编成、存档；可由指定人物确认后推进或选择路线 |
| 音乐 | `{ t: 'bgm', key }` | 换 BGM（`public/assets/bgm/<key>.mp3`） |
| 选择 | `{ t: 'choice', who?, text, options: [{ label, set?, goto? }] }` | 必须点一项；`set` 设标志，`goto` 跳标签 |
| 标志 | `{ t: 'set', flag, value }` / `{ t: 'if', flag, is?, cmp?, goto }` | 没设过的标志按原版当 0 |
| 标签 / 跳转 | `{ t: 'label', name }` / `{ t: 'goto', label }` | |
| 队伍 | `{ t: 'join', id }`、`{ t: 'away', id }`、`{ t: 'level', id, n }`、`{ t: 'class', id, cls }`、`{ t: 'item', id }`、`{ t: 'gold', n }` | 加入、离队、剧情升级、转职、得道具、得金 |
| 单挑 | `{ t: 'duel', a, b, acts }` | 整屏两骑对冲，`acts` 是 `charge / strike / fall / back` 的序列 |
| 营地 | `{ t: 'camp', battle, title, shop }` | 出兵准备：编成、道具、商店、存档 |
| 战斗 | `{ t: 'battle', level, win?, lose? }` | 先出战前说明再开战；胜/败后跳到对应标签。不写 `lose` = 败了重打这一关 |
| 结局 | `{ t: 'ending', text }` | |

- 进度 `Story` 是纯数据：`{ script, pc, section, bg, picture, bgm, cast, flags, roster, party, bag, deploy, gold, resume? }`，
  存档原样写入。`pc` 指向正在等玩家的那一步；`resume: { t: 'battle' | 'camp' | 'room', id }` 是重新生成剧本后仍可定位的稳定锚点。
- **每幕的标签只在幕内有效**。610 幕拼成一条线后重名极多（`won_1` 出现 40 次），
  `build_campaign.py` 给标签和跳转目标都加上 `幕名~第几次出现:` 前缀（如 `c1_s2_story2~0:ask_1`）。
- 原版剧本里的 `@end`（本幕到此为止）会被转成 `goto 幕末#end` 空标签，接上后面的流程节点。
  早期版本这里漏了转换，进军目标的循环菜单会永远跳不出去。
- 装载时 `checkScript()` 查：标签重复、跳转目标不存在、选择没有选项、战斗/营地引用了没登记的关卡。

### 1.1 独立剧情：只加数据

`stories/*.json` 是另一类输入：把文件放进目录就有了一部可运行的剧情，生成器与运行时代码都不用改。
开发模式用 `?story=<id>` 选中它（标题会写成「獨立劇情：劇名」）；生产构建不暴露这个入口。

```json
{
  "id": "lantern-station", "title": "灯塔驿站", "entry": "arrival", "map": "palace/000",
  "actors": { "501": "守灯人", "502": "摆渡人" },
  "sprites": { "501": 9 },
  "phases": {
    "arrival": {
      "enter": [{ "t": "place", "who": 501, "x": 8, "y": 6 },
                { "t": "say", "who": "守灯人", "text": "灯已经点亮。" }],
      "room": { "talks": { "502": [{ "t": "say", "who": "摆渡人", "text": "今夜退潮晚。" }] },
                "exits": [{ "who": 501, "label": "查看路图", "to": "crossroads" }] }
    },
    "crossroads": {
      "enter": [{ "t": "set", "flag": "route", "value": "water" }],
      "room": { "exits": [{ "label": "继续", "confirm": { "who": "摆渡人", "text": "要走吗？" }, "to": "finish" }] }
    },
    "finish": { "end": "你继续前行。" }
  }
}
```

- `compileStory()`（`src/story-source.ts`）把这份数据翻成运行时就有的 `Script` + `StageInfo`：阶段标签是
  `phase:<阶段名>`，舞台 id 是 `story:<id>`，房间锚点是 `<id>:<阶段名>`。没有第二套播放器，
  `nextStep()`、房间等待、舞台动作、存档恢复全部复用原战役那套。
- 指令：`say`、`text`、`caption`、`place`、`move`、`remove`、`clear`、`wait`、`gold`、`set`、`when`。
  `when` 按 `flag/is/cmp` 把 `then` 整段包成条件跳转；`room.talks` 只收 `say`/`text`，可反复点；
  `room.exits` 可挂 `who`（点这个人触发）与 `confirm`（确认框，选否留在原地）。
  每个阶段必须且只能有 `room`、`next`、`end` 三项之一。
- 装载时校验字段名、阶段目标、人物编号、外观号（0–28）、同房间重复触发和空出口，报错带具体字段路径
  （如 `lantern-station.phases.water.enter[0].flag`）。一份写坏的文件只在控制台警告并跳过，
  不拖垮原战役；用 `?story=` 点名它时才抛出完整错误。两份文件同 id 时保留先载入的一份。
- 存档键按剧本加后缀（`yjz.saves.v1@lantern-station`、`yjz.save.v3@…`、`yjz.autosave.v1@…`），
  写档不会覆盖原战役或另一部独立剧情的手动档、最近档与自动档。
- `stories/lantern-station.json`、`stories/watchpost.json` 是两份样例：都是两段交谈、两条路线、
  条件奖励（水路 50 金／山路 0 金，东道 30 金／西道 0 金）。第二份只新增数据文件，
  没有为它改生成器、导入列表或播放器；浏览器回归 `verifyImportedStories()` 同时跑这两份。

  跳转成环、一直不等玩家的脚本，`nextStep()` 报错而不是卡死。

## 2. 关卡

```ts
{ id, name, goal, turnLimit, w, h, terrain: number[], units: UnitInit[], reward,
  map?, tokens?,                       // 素材键（相对 assets/）

  // 旧接口：单主将、单敌将、踩格得金，保留给测试里手写的小关卡
  lord?, boss?, triggers: Trigger[],

  // 整部游戏用这一套
  deploy?: { max, required, forbidden, slots: [x, y][] },
  candidates?: Record<officerId, UnitInit>,  // 可出征的武将模板
  victory?: Victory[], defeat?: Defeat[],
  events?: BattleEvent[], treasures?: Treasure[] }
```

- 槽位沿用原版：0–14 我方（我军 `mode: 7` 由玩家指挥，其余是友军），15–44 敌军。
  友军占 0–14 的高位、出征的我军占 0 起的低位；两拨增援夹在中间，互不撞槽。
- 胜利条件 `commander / all / unit / reach`，任一满足即胜；失败条件 `unit / turn`。
  主将撤退按 `key === 'liu_bei'` 认，其次是关卡数据里的 `lord`。
- 宝物 `treasures`：踩上去就归踩的那支部队（原版只有我方会捡）。
- `registerLevel()` 登记时检查：地形格数、槽位重复、两队同格、站在地图外、兵种不存在、
  引用了不存在的槽位、触发记录重名、出征位不足。

## 3. 战场事件

一场战斗的剧本就是一张 `BattleEvent[]`，全部是数据：

```ts
{ stage?, once?, trigger: { type, … }, actions: BAction[] }
```

| 触发 | 字段 | 何时查 |
|---|---|---|
| `turn_start` | `turn`、`side` | 回合开始（我方阶段） |
| `adjacent` | `a`、`b` | 某部队**行动结束**时，二者四邻相接 |
| `reach` | `who`、`pos`、`radius` | 某部队行动结束时站在目标格（或其半径内） |
| `unit_defeated` | `target` | 某部队被击破 |

| 动作 | 作用 |
|---|---|
| `drama` | 播一幕插剧（对话、插画、单挑、选择，见 §1 的步骤） |
| `flag` | 写战场变量 `b.vars`，战后并回流程 `story.flags` |
| `ai` | 改某部队的 AI 指令、目标格、优先目标 |
| `retreat` / `level` / `item` / `gold` | 撤退、剧情升级、给道具、得金 |
| `halve` | 某一阵营全员兵力减半（原版的火计、伏兵） |
| `spawn` | 增援组登场（就近找空格） |
| `terrain` | 改一格地形（火、水攻、落石） |
| `objective` | 改当前胜利条件并提示 |
| `victory` / `defeat` | 立即判胜/判负 |
| `when` | 先判断若干 `Cond`（读 `b.vars`），成立才执行内层动作 |
| `stage` | 原版用来切换行动方，本作由回合流程控制，保留但不生效 |

`once` 默认 true，触发过就记进 `b.flags` 的 `event:<序号>`。所有事件在**部队行动结束**（含待命）
时统一判定——纯移动不触发，这与原版「行动终了时查脚本」一致。

## 4. 出兵准备（营地）

`camp` 步骤给出这一关的关卡、标题和商店货单（道具号），界面把它渲染成两栏：

- 左栏**编成**：队伍全员列出，`required`（必带）锁定，`forbidden`（不能出战）禁用，
  出征人数上限取 `deploy.max`；
- 右栏**道具**：选中的武将的 8 格包袱 ↔ 公共包袱互转；能转职的道具在名字旁边多一个「轉○○」按钮；
  下面是选中的武将**情報**（武力 / 统御 / 智力 / 等级 / 兵种 / 经验 / 满编兵力 / 已学会的策略条数 /
  已装备的宝物）和**商店**；重画时保留滚动位置，不会每点一下就跳回顶部；
- 底部**存檔**（只存流程）和**出陣**（把名单写进 `story.deploy`，然后进战前说明 → 部队配置）。

商店价格取自原版道具表（`src/data/items.json` 的 `price`，见 §5），不再自己定价：
豆 100、酒 120、麦 250、伤药 300、特级酒 400、米 600、中药 700、老酒 800、茶 1200。
货单也不是网页版排的——原版剧本用 `set_shop_items`（记录 32）换货，换一次一直沿用，
转成剧本数据就是房间和 `camp` 步的 `shop` 列表。序章直接使用原始记录的
`[27,28,29,30,31,32,52,53,54]` 货单，后续69个营地沿用转换包货单。

**开局军资是 0**，不另给启动资金：原版序章里曹操当面拨 500 金（剧本的 `@gold 500`，
台词就是「喂，叫道具屋老闆來」），这笔钱正好赶在第一次进道具屋之前到账，所以第一眼看到的
营地里是 500 金。之后每场战斗只在**胜利**时把军资带回流程：关卡赏金
（`battles/*.toml` 的 `reward_gold`；70 关合计 40000 金，其中 27 关是 0）
加上战场拾得（宝箱与事件给的金）。

## 5. 道具与装备

`tools/build_campaign.py` 把原版的 `rules/items.toml`、`rules/classes.toml` 转成 `src/data/items.json`：

- **63 件道具**：`kind`（weapon 武器 / armor 铠甲兵书 / accessory 马与宝物 / consumable 消耗品）、
  `price`（原版不卖的填 `null`）、`battle`（能否战场上用）、`heal` / `morale`（回复量）、
  `atk` / `def`（攻击力、防御力百分比加成）、`move`（移动力）、`regenHp` / `regenMorale`（参考pack的被动恢复标记，非零有效，不是回复点数或百分比）、
  `promote` / `to`（转职）。
- **装备**：武器 +攻击力百分比、铠甲（兵书）+防御力百分比、马 +移动力，同类只取最高的一件（`rules/core.ts` 的 `bestItem`）。
  武将携带玉玺时每回合恢复150～250兵力及「统御÷10＋1～5」士气；援军报告只恢复兵力，勅命书只恢复士气。
  宝物与恢复地形只合并恢复位，不叠加回复量；重复携带也不叠加。普通包袱库存不生效。原版程序定位见 `docs/rules.md`。
- **消耗品**：豆 600、麦 1200、米 1800 兵力；酒 30、特级酒 40、老酒 50 士气；伤药 600+30、
  中药 800+35、茶 1800+50。数值照原版，另加一成以内的随机浮动；用完从包袱里消失。
  使用范围是自己和周围一圈，档位越高多一圈。
- **转职**：`classes.toml` 的 8 条升级链（短兵→长兵→战车、弓兵→连弩兵→发石车、
  轻骑兵→重骑兵→亲卫队、山贼→恶贼→义贼）各有等级门槛与道具；指南书 / 遁甲天书 / 青囊书 / 鼓吹具
  直接指定兵种。转职只在营地做，用掉道具、改 `roster.cls`，下一战按新兵种出场。
- **策略书**：火龍書、援隊書、大救濟書、爆彈等 19 件道具带 `strategy`，转成 `strategyId` 后直接用对应策略
  （不扣策略值、不需要学会）；爆彈是单独的「爆發」（编号 36，固定 1500 上下）。
- **战斗中的道具指令**：点一件道具弹出「使用 / 给予 / 丢弃」（原版的让渡与舍弃）。
  「使用」只对战场上能用的道具开放，目标与范围同策略；「给予」把道具交给身边一圈（含斜角）的友军，
  接收方最多带 8 件（原版存档记录就是 8 个槽），装备类道具也能给；「丢弃」直接扔掉腾出格子。
  三项都算一次行动，和攻击、策略一样结束这支部队的回合。

## 6. 策略

`tools/build_campaign.py` 把原版的 `rules/strategies.toml` 转成 `src/data/strategies.json`：
37 条策略，0–35 是各兵种按等级学会的，36 是爆彈专用。数值、MP、射程码、作用范围都照原版：

| 类别 | 策略（编号） | 效果 |
|---|---|---|
| 攻击 | 焦熱 / 火龍 / 猛火 … 大山崩（0–14）、爆發（36） | 伤害 = 智力与等级差 + 地形/天气修正，命中判定同下 |
| 混乱 | 假情報（15）、偽兵（16）、偽裝（17，十字） | 命中后混乱；偽裝对目标与上下左右各判一次 |
| 降士气 | 牽制（18）、挑撥（19）、欺壓（20） | -30 / -40 / -50，另加等级÷10 |
| 升士气 | 激勵（21）、支援（22）、鼓舞（23） | +30 / +40 / +50，另加等级÷10 |
| 回复兵力 | 援助（24）、補給（25）、救濟（26） | 兵力 = 威力 + 智力×等级÷20 |
| 回复兼士气 | 看護（27）、治癒（28）、救命（29） | 回复 + 士气同时生效 |
| 群体 | 大激勵 / 大支援 / 大鼓舞（30–32）、大援助 / 大補給 / 大救濟（33–35） | 自己周围所有友军（含自己）一起生效 |

- 回复量再加 0–10% 的随机值；士气量同理，封顶 100。
- 单体回复不能选兵力已满的目标；单体激励不能选士气满且未混乱的目标；群体策略满员也能放
  （原版如此，会白费策略值）。
- 命中：攻击系 `rand(智力修正) > 对方智力修正÷4`；混乱 / 降士气
  `rand((攻方智力修正−1)×2) ≥ 守方智力修正`，智力修正 = 智力 + 等级×智力÷100。
- 经验：单体补给 8 点，军乐队 / 运输队 12 点；群体补给一律 8 点；对敌的混乱 / 士气系命中后 8 点。
- 混乱有两种来源，分开计时：策略造成的混乱按 `strategies.json` 里的 `turns`（原版是 2）数
  自己的阶段，到点必定恢复，期间仍可按 (统御+士气)÷3 提前挣脱；士气跌到 30 以下的混乱没有时限，
  只看每阶段的掷骰。
- AI：受伤的运输队 / 军乐队会先给最需要的人补给；智力 65 以上的军师会远远地放牵制 / 假情報。
- 演出按策略家族分八套（见 §10）：`strategy` 事件只带编号，画面层用 `castMood(id)` 由效果反推家族。

## 7. 队伍继承

- 战斗胜利后，`harvest()` 把玩家指挥过的部队按武将 id 记下等级、经验、道具、兵种，存在 `Story.roster`；
  军资累加进 `Story.gold`。
- 下一战开始时，`deploy` 名单里的武将带着这些出场（兵力和策略值按等级回满）；友军和敌军始终用关卡数据。

## 8. 存档

**存档列表**包含六个手动档与一个独立自动档。手动档键 `yjz.saves.v1`，结构 `{ slots: [SaveEntry | null] × 6, last }`；
`SaveEntry = { story, battle?, at }`，`at` 只用于列表显示时间。旧键 `yjz.save.v3` 继续当
「最近一次存档」的镜像：每次写入 / 删除槽位都同步它，列表空时也会把旧单槽存档接到檔一，
老存档和按旧键预置的自动化流程都能直接读。

- 自动档键 `yjz.autosave.v1`，完整保存 `{ story, battle, at }`，在新战斗及每个我军回合开始、事件结算完毕后更新。
  它不修改手动槽位与最近存档镜像；自动档行只提供读取，禁止手动覆盖与删除，读档本身也不会立刻更新自动档。
- 点「存檔」「存档」「讀取存檔」都打开同一个浮层：存档模式可写入 / 覆盖任意手动格，
  读档模式只让有内容的格可点；每格显示关卡与回合（或出兵准备）、军资、武将数和时间。
  非空手动格带「刪除」，点第一下变成「確認刪除」才真删；Esc 或「返回」收起浮层。
- 营地或自由交谈房间只存流程；商店里保存后读档返回所属房间，购买物品与军资保留。闲谈与动作中不能写档。
  战斗中、我军阶段存 = 连战斗状态（含随机数种子、回合、行动标记、已触发事件）一起存。标题 / 结局不能存。
- `restoreStoryPosition()` 优先按稳定锚点定位，旧战斗档按关卡 ID 定位；无锚点的旧营地档按已存 `section` 和最终路线标志追踪跳转。
  多个战斗变体共用战后片段时检查所有入口，必须汇合到唯一营地及舞台；歧义、循环或无效目标拒绝恢复。
  候选选择仅在标志副本中核验，不重发军资、不重复入队、不改道具。恢复只写 `pc/section/resume`，重复调用保持不变。
- 读档时逐格校验脚本 id、关卡、地形格数、`stage === 'player'`，不合格的格当空档。
- 独立剧情的三处键名都带 `@<剧本id>` 后缀，与原战役及各剧本之间互不覆盖（见 §1.1）。
- 旧键 `yjz.save.v2` / `yjz.sishui.save.v1` 不再识别。

## 9. 布阵（部队配置）

战前说明（`showBrief`）报五项：勝利条件、失敗条件、出征名单，以及**敵情**——开战就在场的敌军有几队、

  棋子位置和比例保持不变，正在移动 / 出手的棋子让给补间，系统要求减少动效时（`scene.speed === 0`）不喘。
- **镜头跟随**：系统菜单提供「镜头跟随 开 / 关」，默认开启并写入 `localStorage`。开启时，移动、攻击、策略和单挑等自动演出会把镜头带到目标附近；关闭时自动演出保持当前视角，但仍可用方向键、鼠标边缘卷屏或按住左键 / 单指拖动画布移动镜头。短按在抬起时才点选；移动超过 7 CSS px 算拖动，抬起不会误下令，指针离开、失焦和触摸取消会清理手势。
  战况栏右侧的小地图绘制本关地形、动画中实际位置的三方部队和金色视野框；点按跳转、拖动视野框平移，方向键可在小地图聚焦时逐两格移动镜头。镜头手动操作在系统菜单、对白、演出或自动跟随时锁住。
- **移动速度**：系统菜单的「移动速度」在 `瞬时 / 很快 / 标准 / 慢 / 很慢` 间循环，写入 `localStorage`
  的 `yjz.anim-speed`。它其实是演出时长倍率（0 / 0.5 / 1 / 1.6 / 2.5），同时作用于棋子走格、特写
  播放与镜头补间；系统要求减少动效时仍强制为 0。
- **简繁显示**：字体本来就是简体字形（`fusion-pixel-12px-zh_hans.woff2`），但原版剧本数据全是繁体。
  `src/zh.ts` 用 OpenCC 的 `t → cn` 在**显示层**转换，默认简体，设置存在 `yjz.script`，
  标题与右下系统菜单都有「文字 简体／繁体」开关。转换挂在 `MutationObserver` 上，任何后加的
  DOM（对白、菜单、状态栏、存档浮层）都自动套用；每个文本节点用 `WeakMap` 记下原文，
  切回繁体是无损还原。属性只转 `title / placeholder / alt / aria-label`，`data-*` 不动，
  避免破坏选择器；Phaser 画布里的飘字与占位地形名单独调 `convert()`。
  数据文件、存档、规则层保持原版繁体不变；**像素图内烧录的字无法转换**。
- **战斗特写**：横幅带淡入滑入、两名演员各自就位；待机是原版帧的 0/-1/-2 三档呼吸再叠一层平滑位移，

  动画关掉跳帧（`skipMissedFrames: false`），掉帧时宁可放慢也不顿一下。
- **移动范围与攻击范围**：选中一支部队，地图上同时亮两片格子——**亮蓝**是可移动范围
  （原版的那个蓝格），**橙**是「走过去能打到的范围」（把每个可停格的攻击范围并起来再减掉
  移动格）。两层都是原版的直角方框，橙格淡一档、不带边框，压在蓝格下面；走完以后只剩
  橙色的可打目标。第一次选人时在战报里说明一次两色的含义，每场战斗重新提示。

## 12. 已知差异 / 还没做

- 布阵只能站到关卡数据给的出兵位上，不能自己另选格子（原版也只在这些格子里摆）。
- 序章前五幕、北海战后及徐州议事厅两条路线已按核对的原始指令顺序播放；第一章界桥篇有六个原始分阶段交谈点，小沛议事厅已恢复两阶段交谈与出发确认，剿匪返城也已恢复奖励、两组交谈与快使报告，吕布来投与钦差到访已恢复各自的三组／四组交谈。其他后续幕尚未全部改为原始时间线。
  城镇自由行走、酒馆打探与通用地点触发尚未恢复；当前用继续按钮接续来访剧情和赴徐州事件。当前203个房间只覆盖已核对的阶段，不代表全部战斗外剧情已完全还原；赴徐州的原始地点参数完整保留但语义尚未解码。
  野外现已使用完整行军地图、道路坐标与跟随镜头；战场插剧仍盖在战场上演出。
  生成器仍有186个 `orig_` 战场事件片段未对齐舞台记录，另7个无对白节点单独跳过；常规章节找到对白候选不代表动作与交互全部完成。
  未知操作码、精确等待与寻路次序尚需与DOS实机核对。读档舞台仍按步骤线性重建；当前203个房间覆盖已核对阶段。小沛议事厅与战后返城已分别通过定向浏览器回归；此前完整 e2e 曾在移动端视口收尾断言停止，本批未全量重跑，其他复杂分支未全面验证。
- 策略的施放演出按八个家族分（见 §10），不是原版逐条策略的专属动画。
- 单挑的招式、位移与收招按 `acts` 表驱动，帧序列取自原版图集，但不是原版逐帧脚本。
- 音乐是原版乐谱离线渲染的 mp3，按场合与阶段选曲（§10），但不是原版 OPL 实时合成；
  胜利没有单独的凯歌曲，交给战后剧本的 `@bgm`。
- **效果音不是原版 DOS 音效**：原版由 `SBOPL2.COM`（KOEI Sound Blaster BGM Driver 1.01）在 OPL2 上
  实时合成。查遍 `MAIN.EXE` 只有 5 处 `int 66h`：`ah=0` 送乐谱、`ah=F0/F1` 设 / 取回调，
  **没有任何单独的效果音调用**；驱动里虽然有一套两通道的 SE 播放器（`ah=10h–13h`，通道 7/8），
  但全盘没有调用者，也没有自带音色表，所以效果音无处可抽。现用 21 个 CC0 音效按动作替代。
- 没有实机运行过原版做逐帧对比（规则依据见 `docs/rules.md` §4）。

## 13. 修改器

画面左上角有一块 44×44 的隐形热区，连点三下弹密码框，输入 `1122` 打开面板。标题、营地、
战场上都能开；密码只防误触，不是安全措施。它改的是 `Story`（军资与 `roster`），
所以存读档、战后结算、下一战的出兵都与正常流程同一套数据。

- **军资**：直接输入，或 ＋1000 / ＋10000 / 归零。
- **武将**：队伍里每人一行，可改等级（1–99）、经验（0–99）与兵种（原版 19 种）。
  「一鍵裝備」给每个部位换最好的一件：包袱里有就用包袱里的，没有就发最强的那三件
  （霸者劍 / 孫子兵法 / 赤兎馬）；同时补齐一件玉璽（每回合恢复150～250兵力及统御÷10＋1～5士气，不占装备位），
  已经带着就不重复发、多出来的回包袱。换下来的旧装备放回包袱，已经穿着最好的再点不会重复发。
- **道具**：从完整道具表（63 件，按兵器 / 防具 / 馬 / 其他分组）往包袱里放 1–99 个；
  另有「全部道具各 1」「消耗品各 10」与「清空包袱」。
- **战场**：战斗中改等级 / 兵种 / 道具会同步到战场上同一支部队，兵力和策略值按新上限补满；
  「我軍補滿」把在场友军的兵力、策略值、士气补满并解除混乱。营地与剧情画面背后也挂着一场
  背景战，那时不显示这个按钮。
- 纯逻辑在 `src/trainer.ts`（密码、范围、装备位、一键装备、`syncUnit`），面板只负责排版；
  `tests/trainer.test.ts` 11 项覆盖，e2e 另有一项从真实点击热区开始走完整条路。
